👥 Roles & Portals

Admin Side — /admin/login

  • SUPER_ADMIN — Full control, users, money, all
  • ADMIN — Platform mgmt, vendors, bookings
  • SUB_ADMIN — Assigned region only
  • MANAGER — Assigned location + service
  • EDITOR — Content only (blog, SEO, pages)

Vendor Side — /vendor/login

  • Email + Password login
  • Status: PENDING → DOCUMENTS_PENDING → UNDER_REVIEW → APPROVED
  • Staff roles: DRIVER, HELPER, MECHANIC, SUPERVISOR, OFFICE_STAFF
  • Manage fleet, bookings, staff, earnings, social

Customer Side — /login

  • B2C Customer — Regular, browse & book
  • B2B Customer — Corporate, bulk + wallet
  • B2B approval required from Admin
  • Mobile App (React Native) + Web

Driver — /driver/login

  • Phone + OTP login
  • Web dashboard only (no mobile app)
  • View assigned bookings
  • OTP-based trip start/end
  • Track earnings per booking

PAYMENT FLOW

1

Customer pays via Razorpay

30% advance of (Base + 18% GST). Razorpay returns order_id + payment_id + signature

2

POST /api/payments/verify

System verifies HMAC signature. If valid → DB update: status=PAYMENT_VERIFIED, paymentStatus=PAID

3

Auto-notify vendor (if pre-assigned)

If vendor already assigned from quote → direct FCM notification sent immediately

4

Admin broadcasts (browse-first only)

If no vendor assigned → Admin manually triggers broadcast from dashboard

⚠️ This is the manual delay bottleneck
5

Balance payment at completion

Remaining 70% + any extra charges paid after trip ends

🧩 Additional Modules
🏢

B2B Corporate

Bulk Bookings + Wallet
  • HR creates bulk booking request (multiple vehicles)
  • Vendors bid with super-quotes
  • HR accepts → trips auto-created (1 per vehicle)
  • Driver assigned per trip, OTP-based start
  • Payment via prepaid wallet or Razorpay
  • Auto invoice: DRAFT → ISSUED → PAID
  • Wallet: RECHARGE / BOOKING_DEBIT / REFUND
🧭

Wander

Tours & Experiences
  • Vendors create tour listings (itinerary, pricing, images)
  • Customer browses by category / location / date / price
  • Customer requests quote
  • Vendor responds with custom quote
  • Customer books + pays via Razorpay
  • Reviews after tour
  • Wishlist to save favourite tours
🔁

P2P Marketplace

Vendor ↔ Vendor
  • Vendor A posts vehicle with empty seats/space
  • Vendor B browses available vehicles
  • B requests to use A's vehicle
  • A accepts → transaction created
  • Trip starts, completes, both rate each other
  • Use case: share trip costs on same route
📣

Social

Vendor Community
  • Vendors create posts (tips, news, general)
  • SOS posts — emergency alerts, expire in 24hrs
  • Like, comment, save posts
  • Follow other vendors
  • Direct messages (1-on-1 DM)
  • Admin manages categories
